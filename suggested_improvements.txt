Suggested improvements for public package API classes

Scope:
- This file lists non-implemented recommendations only.
- Focused on ConfigParams, Dataset, and MergeMethods.
- Includes style, naming, consistency, correctness, robustness, and packaging concerns.

==================================================
Class: ConfigParams
==================================================

1. Add input validation in __init__
- Validate numeric ranges and relationships:
  - reg_lmax >= 0
  - win_lmax >= 0
  - win_eff_lmax >= 1
  - win_eff_lmax <= win_lmax when spherical windows are used
- Validate coordinate bounds:
  - lon_bounds and lat_bounds should each have exactly 2 values
  - ensure min <= max
  - check longitude and latitude domain validity (for example, lon in [0, 360] or [-180, 180], lat in [-90, 90])

2. Tighten type hints
- tuple[float] should be tuple[float, float] for lon_bounds and lat_bounds.

3. Validate win_type explicitly
- Restrict to allowed values ("spherical", "rectangular") and raise ValueError for anything else.

4. Improve API ergonomics
- Consider using a dataclass (frozen optional) to simplify this pure configuration container.
- Consider naming consistency with Python style:
  - if exposing this broadly, prefer snake_case naming in constructor arguments and attributes.

5. Add class-level documentation for units and conventions
- Document expected longitude convention and depth unit assumptions used by downstream classes.


==================================================
Class: Dataset
==================================================

1. Potential correctness bug: convert_units is called with None by default
- __init__ default depthUnits is None, then convert_units(depthUnits) is called unconditionally.
- convert_units currently raises unless input is "m" or "km".
- This can cause immediate initialization failure for common default usage.

2. Potential None dereference in regional initialization
- In __init__, when modelType is REGIONAL and depths is None, code reads globalModel.getDataset().depth.values.
- If globalModel is None, this will fail with AttributeError.
- Should validate globalModel presence when required.

3. Inconsistent/legacy naming style for public API
- Public constructor and methods use camelCase names (filePath, modelType, getDataset, etc.) while Python ecosystem expects snake_case.
- For published package quality, consider snake_case methods and parameters (possibly with compatibility aliases).

4. Overly broad and unused imports
- Multiple imports appear unused in this module (examples: yaml, pyshtools, sys, pandas, netCDF4, pdb, Model1D, RectBivariateSpline).
- Cleaning these improves startup/import time and maintainability.

5. getInterpolationParameters edge cases and typing
- depths annotated as list[int], but depths may be non-int values in practice.
- target_reg_increment is computed from floating spacing and cast to int; this can produce low-resolution or off-by-one grids.
- np.linspace(-180, 180, N) includes both endpoints; depending on later processing, this may duplicate wrap-around longitudes.

6. interpolate_slice should be explicitly static or include self
- Method is defined without self and without @staticmethod, but used like a static function.
- This is confusing for maintainers and API readers.

7. interpolate_model coordinate construction bug risk for 2D fields
- DataArray coordinates always include a depth coordinate tuple, even when target_depths is None and interpolated_data is 2D.
- This can lead to coordinate/dimension mismatch.

8. interpolate_model does repeated sorting inside per-variable loop
- new_ds = new_ds.sortby("latitude", ascending=True) runs for each variable.
- Move this outside the loop for efficiency and clarity.

9. convert_longitude could leave unsorted coordinates
- After converting negative longitudes to [0, 360], longitudes may become non-monotonic.
- Sorting by longitude after conversion would make downstream interpolation/selection safer.

10. assign_names may rename ambiguous variables
- It checks self.dataset.variables, which includes data variables and coordinates.
- If a data variable happens to match a coordinate alias, rename behavior may be surprising.
- Consider checking coordinates and dimensions explicitly.

11. convert_units behavior should be explicit and idempotent
- Current conversion divides depth and optionally VSV/VSH when depthUnit == "m".
- If called more than once with "m", values will be scaled repeatedly.
- Consider tracking units or adding guards against double conversion.

12. plot_variable and plot_all_variables show/close behavior is inconsistent
- plot_variable may call plt.show() for newly created figures.
- plot_all_variables may call plt.show() again, leading to duplicate rendering behavior.
- Consider single-point control of rendering in one layer only.

13. save_model does not validate output path/permissions
- Optional checks and clearer exceptions would improve user-facing error messages.

14. Exception specificity and messages
- Several ValueError messages are generic (for example, "Need to pass in file path").
- More actionable messages would improve package usability.

15. Improve public API typing and return annotations
- Add explicit return types for methods currently missing them.
- Use collections.abc.Sequence where appropriate for broader input compatibility.

16. Add tests for key failure modes
- Initialization defaults, missing global model, coordinate detection failures, depth interpolation edge cases, longitude wrapping, and plotting behavior.


==================================================
Class: MergeMethods
==================================================

1. Constructor variable detection can silently overwrite model assignment
- If both inputs are same model type, regional_mod/global_mod assignment logic can overwrite prior values before final validation.
- Validation exists, but explicit branching could be clearer and less error-prone.

2. Public API naming consistency
- Similar to Dataset, method and argument names mix camelCase and snake_case patterns.
- Standardizing improves package consistency.

3. Overly broad and unused imports
- Several imports appear unused (examples: multiprocessing, os, concurrent.futures, time, sys, yaml, pandas, pdb).
- Remove dead imports for maintainability.

4. convert_to_spherical_harmonics mutates caller input
- zmesh is modified in place when NaNs are filled.
- In-place mutation can create hard-to-track side effects; consider copying before modification.

5. Potential NaN fill failure case
- If zmesh is all-NaN, np.nanmean returns NaN and filled result remains NaN.
- Add a guard for fully missing slices.

6. create_window computes unused variable
- reg_win_clm_pad is assigned in spherical branch but not used.
- Remove or use intentionally.

7. create_window missing explicit invalid win_type handling
- Only "spherical" and "rectangular" branches exist.
- Any other value leaves reg_win_energy_grid undefined and later crashes.
- Raise ValueError for unsupported win_type.

8. apply_window takes an unused argument
- global_grid is not used in apply_window.
- Remove unused parameter or use it intentionally.

9. process_slice depth-range logic may fail for shallow depths
- Condition uses depth <= max(regional_depths), but does not check lower bound.
- For depth values below regional min depth, selection may fail.

10. Depth selection is exact float match
- reshape_field uses .sel(depth=float(depth)) without nearest/tolerance.
- Floating-point coordinate mismatch can throw KeyError.
- Consider nearest selection with tolerance.

11. merge implementation/comment mismatch
- Comments discuss multiprocessing/thread pool, but implementation is fully sequential.
- Either restore controlled parallelism or update comments to match behavior.

12. merge prints directly to stdout
- print("depth - ", depth_val) is noisy for library users.
- Prefer logging with configurable level.

13. write_model docstring does not match actual output type
- Docstring says "3 columns: lon, lat, dv", but method returns xarray.DataArray with 3 dimensions.
- Update documentation for accuracy.

14. Hard-coded output variable names are inconsistent
- write_model returns name="dv", later converted to dataset name="merged" in merge.
- Consider clear, consistent naming or making output names configurable.

15. Tighten method typing and contracts
- Add type hints for arrays/grid/clm objects and return types across helper methods.
- This helps users and static analyzers when package is published.

16. Add targeted tests for merge boundary conditions
- Invalid window types, all-NaN slices, non-matching depth coordinates, out-of-range depths, and merge output metadata.


==================================================
Cross-class/API publication recommendations
==================================================

1. Define and document public API surface
- Decide which methods are public vs internal and mark internals clearly (leading underscore).

2. Add consistent error model
- Use clear exception types/messages across all classes with actionable context.

3. Centralize unit/coordinate conventions
- One authoritative location for depth units and longitude conventions to avoid drift.

4. Ensure import-light top-level modules
- Public import paths should avoid loading heavy plotting/geospatial dependencies unless needed.

5. Add package-level tests before release
- Include smoke tests for end-to-end merge and unit tests for validation, interpolation, and window creation logic.
